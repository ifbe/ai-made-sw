## 1. 它是什么，不是什么

| 是 ✓ | 不是 ✗ |
|---|---|
| 一个**块/文件级**的存储层：按偏移读写 ✓、目录当命名空间 ✓、**一次块写 = 一次原子提交** ✓ | 不是 SQL 数据库 ✗、没有查询语言 ✗、没有类型系统 ✗ |
| **崩溃安全**的：不覆盖已提交内容（按 COW 运行时 ✓）、位图可重建 ✓、`fsck` 可查 ✓ | 没有**跨对象事务** ✗、没有日志重放 ✗、没有两阶段提交 ✗ |
| **可快照**：按世代保留整棵树 ✓（[`feature-snapshot.md`](feature-snapshot.md)）| 没有自动 MVCC ✗（快照是显式动作 ✓）|
| **可移植**：4 KiB 块、单一格式、只要求载体"按偏移读 / 写" ✓ | 没有 `fsync` 屏障语义 ✗（见 §5）、没有多进程文件锁 ✗ |

**一句话** ✓：EasyFS 给你的是「**原子的提交点 + 可快照的命名空间**」✓ ——
事务语义、索引、并发控制这些**由你在它上面设计** ✓。

## 2. 能直接用的四个原语

| 原语 | 怎么用 |
|---|---|
| **原子提交点** | 让"一次提交 = **一个块的写**" ✓：把可变状态都挂在**一个根**后面（一个链接块 / 一个文件 ✓），改完只换那个根 ✓ |
| **范围读写** | 对 ②③ 模式（内联 / 直接指向 ✓）**读和覆盖写都便宜** ✓；按 `--cow` 运行时覆盖写变"读旧 → 复制 → 重映射" ✗（对 MVCC 友好 ✓）|
| **命名空间** | 目录树 = 表 / 库的层次 ✓；条目 = 小记录（内联 ≤ 255 B ✓）；大记录用文件 ✓ |
| **快照** | 记下当时的世代号 ✓ ⇒ 之后按那个世代读 ✓（一致性读 / 时间点恢复 ✓）|

## 3. 三种集成方式（由简到繁）

### 3.1 一文件一表（最简）

* **表 = 一个文件** ✓，**行 = 文件里的记录**（定长或带长度前缀 ✓）；小行也可以一条目录条目 ✓；
* 提交 = 写完数据后，最后写一次"**头记录**"（长度 / 校验 / 版本 ✓）✓ —— 头指针换一下就是提交 ✓；
* 适合：**单写者、行数不太大、整表重写可接受** ✓。

### 3.2 页文件（推荐）

* **一个文件 = 一张表的页文件** ✓：页 = 文件内固定偏移 ✓（`page_no × page_size` ✓）；
* 提交 = **只改"页目录 / 根页"** ✓（一次块写 ✓），数据页本身按 COW 写新页 ✓；
* 页目录不要用"链表" ✗（会把邻居耦合带回来 ✗）⇒ 用**树**（键 = 页号 ✓），或干脆每层一个文件 ✓；
* 适合：**有自己 B-tree / LSM 的存储引擎** ✓（EasyFS 只当"页的容器 + 提交点" ✓）。

### 3.3 影子文件 + 提交点（最稳）

* 每次提交写一个**新版本文件** ✓（影子 / `shadow` ✓），成功后只把"**当前版本**"这个指针换掉 ✓；
* 指针本身放哪 ✓：一个很小的"**目录文件**"（一条记录：`当前版本名 / 校验 / 世代`✓），它的提交就是一次块写 ✓；
* 旧版本按**延迟释放**回收 ✓（快照机制 ✓），不立刻删 ✓；
* 适合：**要求"提交后旧数据仍可读"**（一致性读 / 备份 ✓）。

| 方式 | 提交粒度 | 空间 | 适合 |
|---|---|---|---|
| 3.1 一文件一表 | 整个文件 | 省 ✓ | 小表、批处理 |
| 3.2 页文件 | 一页 + 根页 | 中 ✓ | 自研存储引擎 |
| 3.3 影子文件 | 一版 | 费 ✓（靠延迟释放回收 ✓）| 强一致读 / 备份 |

## 4. 事务与崩溃一致性

**能保证的** ✓：

1. **单提交点原子** ✓ —— 一次块写成功 ⇒ 新状态整体可见 ✓；
2. **已提交内容不被原地覆盖** ✓（按 COW 运行 ✓）—— 半途崩溃看到的要么是新、要么是旧 ✓；
3. **不需要日志重放** ✓ —— 位图是派生数据（I3 ✓），崩了重扫就行 ✓；
4. **撕裂写可检测** ✓ —— 块头 CRC（+ 链接块的 A/B 双槽 ✓）能识别半写块 ✓。

**不能保证的** ✗：

* **跨多个提交点的一致性** ✗ —— 两次独立提交之间崩溃 ⇒ 可能"前一半生效、后一半没生效" ✓
  ⇒ 解法：**把所有可变状态挂在一个提交点后面** ✓（3.2 的根页 / 3.3 的目录文件 ✓）；
* **硬件原子性** ✗ —— 4 KiB 写对某些介质**不是**原子的 ✓ ⇒ 依赖 CRC / 双槽**检测** ✓、而不是假设它原子 ✗；
* **写序的持久性** ✗ —— 载体只承诺"按偏移写" ✓，不承诺"先 A 后 B" ✓（见 §5 ✓）。

## 5. 不要依赖的语义（踩了就坏 ✗）

| 不要 ✗ | 原因 | 替代 ✓ |
|---|---|---|
| `fsync` / 写屏障 | 载体接口里没有 ✓（只有 `flush` ✓）| **用提交点**：写完数据 → 写一次根 ✓（不依赖顺序 ✓）|
| 稳定的文件号 / inode 号 | 没有 inode ✓（[`proscons.md`](proscons.md) P5）| 用**路径** ✓ 或自己维护"名字 → 记录"的映射 ✓ |
| 大段连续预分配 | 分配单位是 `chunk` / 粗粒度单位 ✓，没有 `fallocate` 语义 ✗ | 按需分配 ✓ + `optimize` 整理 ✓ |
| 多进程并发写 | 没有跨进程锁 ✗ | **单写者** ✓ + 多读者走**快照世代** ✓ |
| "删了立刻回收" | 有保留世代时是**延迟释放** ✓ | 等旧世代不再被引用 ✓（快照机制 ✓）|

## 6. 空间与回收

* 位图是**派生**数据 ✓（可从引用结构重建 ✓）⇒ 允许脏 ✓、允许过期 ✓；
* 有快照时靠**按世代的延迟释放** ✓（[`feature-snapshot.md`](feature-snapshot.md)）⇒ 空间不会被立刻收回 ✓；
* 碎片靠**显式整理**（`optimize` ✓）⇒ 数据库场景建议**定期整理** ✓（在"没有长时间保留的世代"时 ✓）；
* 小记录优先**内联**（≤ 255 B ✓）⇒ 省掉一整块 ✓；但**不要**把大记录塞进目录条目 ✗（条目上限 ~4032 B ✓ 且会走跨块欠账 ✗）。

## 7. 概念对照表

| 数据库概念 | 在 EasyFS 上对应什么 |
|---|---|
| 库 / 表 | 目录 ✓ |
| 行（小） | 目录条目 ✓（内联 ≤ 255 B ✓）|
| 行（大） | 一个文件 ✓（或对象形态的链接块 ✓）|
| 页 | 文件内固定偏移 ✓ |
| 页目录 / 根页 | 一个文件（或链接块）✓ —— **提交点** ✓ |
| 索引 | 应用层自己做（B-tree 落在页文件里 ✓）|
| 事务提交 | **一次块写**（换根 / 写目录文件 ✓）|
| WAL | **影子文件**（3.3 ✓）—— 不需要日志重放 ✓ |
| MVCC / 一致性读 | **保留世代**（快照 ✓）|
| 检查点 / 校验 | `fsck` ✓ + 数据块上的 `CRC32` 属性 ✓ |
| 空间回收 | 延迟释放 + `optimize` ✓ |

## 8. 待定项

1. **页大小的建议值**：跟 `chunk` 一致（4 KiB ✓）还是跟介质页（4–16 KiB ✓）对齐 ✓；
2. **记录级校验**：每行一条 `CRC32` ✓ 的代价 vs 每页一条 ✓；
3. **"目录文件"要不要标准化**（一套"当前版本指针"的约定 ✓）⇒ 多个应用可复用 ✓；
4. **与 `--cow` 的关系**：数据库场景建议**始终按 COW 运行** ✓（否则覆盖写会毁掉旧版本 ✗）；
5. **多读者并发**：只读挂载 ✓ / 快照 ✓ / 应用层共享内存 ✓ —— 需要实测取舍 ✓。
