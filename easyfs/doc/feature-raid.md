## 1. 目标场景

**6 块硬盘，每块一个分区 → 组成一个 `raidz2`（4 数据 + 2 校验）→ 任意 2 块坏仍可读。**

```
        ┌──────────────── 一个逻辑块设备（vdev）────────────────┐
硬盘1..6 各一个分区 ──► RAID-Z2 地址映射（数据/校验列在盘间轮转）
                          │
                          ▼
                   EasyFS **一个**卷（一个 region、一对 anchor、一张位图）
```

⚠️ 两个前提必须说清：

1. **RAID 在文件系统下面**：是"6 个分区拼成一个设备，EasyFS 在上面"，
   **不是**"6 个 EasyFS 卷互相复制"（后者不是 RAID：没有条带、没有校验列）。
2. **"坏 2 盘可读"分三层能力**，不是一件事：

| 层 | 能力 | 本文档阶段 |
|---|---|---|
| ① 拓扑自描述 | 任意 4 块盘就能知道"这是谁的池、怎么排的列" | **P0**（本文主要提案）|
| ② 降级读取 | 缺员时按校验重建、能挂载 | **R1** |
| ③ 写安全 + 自愈 | 掉电不产生坏条带；静默损坏能发现并修 | **R2 / R3** |

**初版（本文）只把 ① 的位置和语义定下来**；②③ 是横切改动，单独排期（§8）。

## 2. 与 ZFS 的对照：缺什么

### 2.1 ZFS 那边靠哪些构件

| 构件 | 做法 | 作用 |
|---|---|---|
| pool / vdev | 池由 vdev 组成；vdev 可为单盘 / mirror / raidz1-3 | 冗余粒度 |
| **label（每盘 4 份）** | 头尾各 2 份，内含池配置 nvlist | **任意子集都能组装拓扑** |
| uberblock + TXG | 每个 vdev 头 4 个轮转的 uberblock，带单调 txg，取最高有效 | 崩溃后选最新一致点 |
| block pointer（DVA + checksum）| 校验和随块指针存；读时校验，坏了用冗余重建 | **自愈**的前提 |
| raidz map | `逻辑偏移 → (列 → 盘, 单元偏移)`，**变宽条带**，末条带可短 | 地址映射 |
| **full-stripe write** | 永远整条带写新空间，从不读-改-写校验 | 避免 RAID-5/6 写洞与 RMW |
| **COW + TXG** | 活数据永不原地覆盖；父指针最后提交 | **根治写洞** |
| metaslab 分配器 | 按条带几何做大块顺序分配 | 性能 / 对齐 |
| scrub / resilver | 走**块树**（只验已分配块）| 修复与换盘 |
| ditto blocks | 元数据默认 2–3 份 | 元数据抗损 |
| ashift / 对齐 | 扇区与条带对齐 | 正确性 |
| replace / spare / online | vdev 级运维 | 恢复冗余 |

### 2.2 基础设计已有的（决定缺口的形状）

| 已有 | 对 RAID 的价值 |
|---|---|
| `L` 是逻辑坐标（i64）| **形状正是 vdev 逻辑偏移** —— 映射层的输入模型已经对了 ✓ |
| 设备接口已抽象（`size/read_at/write_at/flush/close`）| 可以在设备层插 `VdevDevice`，格式层不知情 ✓ |
| **位图是纯派生数据（P4）** | scrub/resilver 的天然基础：可达集合 = live set，可只走树 ✓ |
| anchor 自描述（uuid / generation / head-tail 互指 / 区域几何）| 已是"label 的雏形" |
| `CRC32` 属性已注册（`0x33`；写侧尚未使用）| 校验和可放**父指针**（目录条目 / 链接块），结构不用改 ✓ |
| 提交点 = 最后一次元数据块写 | 与"条带写完再写父指针"同源 ✓（但见 §3 写洞）|
| `PADn` / 链式续段 | 与 RAID 无关，但影响 scrub（"删了没压实"的字节算不算 live）|

### 2.3 缺失清单（分层）

| 层 | 缺什么 | 缺了为什么不行 |
|---|---|---|
| **A 池 / vdev** | 拓扑描述、**每成员标签**、成员身份、缺员降级挂载 | 基础设计里 anchor 只有一对、且在**同一个设备**上；坏 2 盘可能连锚点都没了 |
| **B 映射** | `L → [(成员, 偏移)]` 条带映射、两路校验、读时重建 | 没有它，"逻辑地址"落不到物理成员上 |
| **C 分配** | 整条带分配、条带对齐、逻辑/物理空间账 | 4 KiB chunk 单独成条带 = 33% 效率 + 3× 写放大 |
| **D 一致性** | 条带级提交（或 COW）、跨设备写序 / flush 语义 | **写洞**：半写条带在之后坏盘时重建出垃圾 |
| **E 校验自愈** | 每块数据校验和（且校验和自身冗余）、"哪块盘坏了"的判定、scrub | 没有校验和只能识别"盘不见了"，识别不了静默损坏 |
| **F 运维** | replace / spare / online / offline / 错误计数 | 没法恢复冗余 |

### 2.4 能力对照表

| # | "坏 2 盘仍可读"的必要条件 | 基础设计 |
|---|---|---|
| 1 | 拓扑能从任意 4 盘读出 | ✗ 只有一对 anchor，同设备 |
| 2 | `L → 成员 + 偏移` 的确定性映射 | ✗ 无 |
| 3 | 两路校验与重建算法 | ✗ 无 |
| 4 | 每个被引用条带的校验**有效**（无写洞）| ✗ 原地覆盖、无 COW/事务 |
| 5 | 每块校验和，且校验和自身冗余 | ✗ 数据块无校验（`CRC32` 属性已注册，写侧未用）|
| 6 | 缺员时能挂载（不拒绝）| ✗ `ESTALE` / 尺寸守卫直接拒 |
| 7 | 元数据（anchor / 位图链 / 目录 / 链接块）冗余 | ✗ 单份 |
| 8 | 能重建回满冗余（resilver / replace）| ✗ 无 |

## 3. 与基础设计**正面冲突**的取舍

| 现有特性 | RAID 下的处境 |
|---|---|
| **P2 双向伸缩便宜 / P1 卷内无绝对地址** | 两端伸缩失去意义：扩的是**成员**不是边界；`L↔P` 变成 vdev 映射。**P2 价值进一步下降，`L` 的价值上升** |
| **head/tail 一致性（I9）** | 基础设计是"两份不一致 ⇒ 拒绝挂载"；池成员需要**允许降级挂载**：某份标签不可用就按 §6 的池仲裁取最高有效 `gen`（普通单卷仍按 I9，不挑赢家）|
| **P7 数据块零开销** | 自愈要数据校验和 → 用 `CRC32` 属性放在**父指针**上（结构不用改，但写路径都要记）|
| **分配单位 < 整条带** | 必须让分配**按整条带对齐**（最小分配 ≥ 16 KiB）；`bit_unit` 已可粗于 `chunk`（见 [`1-alloc.md`](1-alloc.md) 的混合粒度一节），`chunk` 本身不必改 |
| **C1 单写者、无事务** | 条带写天然跨 6 个设备协同，需要事务点 |
| **P4 位图是派生数据** | **加分**：坏盘后位图可重建；前提是元数据本身还有冗余 |
| **"一次 4 KiB 块写 = 提交点"** | 提交点变成"一条条带 + 父指针"，粒度变了 |

## 4. 6 盘 raidz2 的具体数字（4 KiB 单元）

| 写法 | 物理占用 | 容量效率 | 写放大 | 评价 |
|---|---|---|---|---|
| 每个 4 KiB chunk 单独成条带 | 1 数据 + 2 校验 = 12 KiB | **33%** | **3×** | 基础设计的分配单位（chunk）会直接落到这里 ✗ |
| 整条带写（4 数据 + 2 校验 = 24 KiB）| 16 KiB 数据 + 8 KiB 校验 | **66.7%** | 1.5× | ZFS 的做法：要求**分配单位 ≥ 16 KiB 且条带对齐** ✓ |

再叠上"默认是原地写"→ 改一个 4 KiB 块会变成**读-改-写校验**（读旧数据 + 读旧校验 + 算新校验 + 写 4 个单元）。
**注意**：COW 已经进设计了，但**由运行参数决定**（`--cow`，[`feature-cow.md`](feature-cow.md)）——
若要把 RAID 的写洞从根上消掉，就得让**整卷都按 COW 运行**（代价见 [`feature-cow.md`](feature-cow.md)）。
**这是最容易被低估的地方**：它不是"加一层映射"，而是**重新定义分配与写路径**。

派生结论：**位图要按"条带"记，而不是按 4 KiB chunk 记**（否则逻辑容量与物理容量对不上）。

## 5. 锚点块内的 pool 段（本文主要提案）

### 5.1 块内布局（两大段：卷头 + pool 段）

anchor 块是 **tag 流**（[`5-anchor.md`](5-anchor.md)）：8 字节 ASCII 名 + 值，每个字段 16 字节。

```
anchor 块（4096 B）
[0x000, 0x200) 【卷头】 = 头基本信息 + 几何/身份段 + 状态段   ← hdrcrc 覆盖（512 B）
[0x200, 0x3d0) 【pool 段】 = easypool + 成员字段 + 成员表     ← poolcrc 覆盖
[0x3d0, 0x1000) 留空
```

**两个魔数分工**（各自都是所在段的第一个 tag）：

* **`easypart`**（`[0x000,0x00f]`）—— "这块属于一个 easypart 卷"，值是版本字符串；anchor 这类块共用；
* **`easypool`**（`[0x200,0x20f]`）—— "这个卷是一个 pool 成员"；**没有它 = 普通单卷** ✓

看到 `easypart` + `easypool` ⇒ 它是 easyraid 池的成员；只有 `easypart` ⇒ 普通单卷。

选 `0x200` 起的好处：**512 对齐**（工具可只读这一段）；**卷头与非 RAID 读者无关**
（普通卷只读前 512 B）；**段起点固定**（好写、好查、好做一致性检查）；**pool 段不常变**（只有拓扑变更才写）。

### 5.2 校验与覆盖

| 谁 | 覆盖范围 | 说明 |
|---|---|---|
| `hdrcrc` | **卷头** `[0, 0x200)` | 一票决定卷头真假；**不含 pool 段** ⇒ 非池卷完全不用管 `[0x200,…)` 的字节 ✓ |
| `poolcrc` | **pool 段** `[0x200, 0x3d0)` | 池成员自己的校验；紧跟 `easypool`（`[0x210,0x21f]`）⇒ **先验 CRC，再信后面的字段** ✓ |

**不需要再加 flags bit**：`easypool` 这个 tag 本身就是"含 pool 段"的判据 ✓
（非池成员该段全零 ✓）；通用头 `flags.bit2` **不表示** pool 段（保留）✓。

> **成员状态（replacing / read-only / removed）不写进格式** ✓ —— 它是运维瞬时状态，
> 由管理员 / 上层软件记（**不写进格式**）。

### 5.3 pool 段字段（`[0x200, 0x3d0)`）

完整表见 [`5-anchor.md`](5-anchor.md) **大段二**，要点：

| tag | 值宽 | 说明 |
|---|---|---|
| `easypool` | 8 | 版本字符串；**有它 = 池成员** |
| `poolcrc` | 8 | u32，覆盖 `[0x200, 0x3d0)` |
| `memindex` / `memcount` | 8 / 8 | 本成员在 vdev 里的槽位 / vdev 成员数 N |
| `vdevtype` / `nparity` | 8 / 8 | 0 单盘 1 mirror 2 z1 3 z2 4 z3 / 校验列数 |
| `ashift` / `stripe` | 8 / 8 | 物理扇区 `2^ashift` / 条带单元字节数 |
| `topover` / `memmapct` | 8 / 8 | 映射规则版本 / 成员表有效项数 |
| `memmap00` … `memmap15` | 8 ×16 | **"列号 → 成员 GUID"权威表**（每项 8 字节成员号）|
| （无 tag）| 16 ×3 | 段末三个**裸 uuid**：池 / vdev / 成员 |

## 6. 组装与仲裁（提案）
1. **找标签**：每盘头 / 尾各 1 份（将来可 4 份）；按 `magic` + 偏移扫描。
2. **仲裁规则**（坏 2 盘后靠它挑出真相）：
   * 只认 `hdrcrc` / `poolcrc` 有效的标签；
   * 取 **`gen` 最高**的；同 `gen` 取**副本序号最大**的；
   * `clean` 取**最保守**（任一成员说 dirty ⇒ 整个池 dirty，触发位图重建）；
   * **同 `memindex` 出现两个不同 `成员 uuid（裸值）`** ⇒ 以 `memmap00…15`（成员表） 为准，
     另一个判**陈旧 / 伪造**，**拒绝并报警**（绝不允许猜）。
3. **拓扑一致性**：所有成员的 段末裸池 uuid / 段末裸 vdev uuid / `vdevtype` / `nparity` /
   `memcount` / `stripe` / `ashift` / `topover` 必须一致；不一致 ⇒ 拒挂。

> 这条"取最高 `gen`"是**池成员的仲裁**（缺员降级时才允许）；
> 普通单卷仍按 [`5-anchor.md`](5-anchor.md) 的 I9：head / tail 不一致**一律拒绝**，不挑赢家。

## 7. 地址映射（提案 · 纯函数）

`L` 已经是卷内逻辑坐标 ✓ 于是（一个 pool = 一个 vdev 的情形）只需要一个**纯函数**：

```
stripe_id   = L_byte // (stripe * (N - nparity)) # 第几条条带
col_in_stripe = ...                                          # 数据列序号
disk        = (col_in_stripe + rot(stripe_id, N)) % N        # 列轮转（topover 决定规则）
offset      = partition_off + stripe_id * stripe + ...  # 单元偏移
```

* 校验列 = 条带里最后 `nparity` 列（数据列优先），**末条带可变短**。
* `rot()` 的规则由 `topover` 决定 —— 将来改布局必须换版本号，老盘才能被识别。
* 多 vdev 时还需要 **vdev 范围表**（待定项）。

## 8. 最小路线（分阶段）

| 阶段 | 做什么 | 得到什么 | 风险 / 代价 |
|---|---|---|---|
| **R0 拓扑自描述** | pool 段（§5）+ 每成员标签 + 仲裁规则（§6）| 任意 4 盘能判"这是谁的池、怎么排的列"；能**主动拒绝**假成员 | 纯格式改动（建议尽早定稿）|
| **R1 降级读取** | `VdevDevice`（设备层）+ 条带映射 + 校验重建 + 缺员挂载 | **坏 2 盘仍可读**（前提：无半写条带、元数据所在条带完好）| 设备层大改；读放大；`ESTALE` 语义要放宽 |
| **R2 写安全** | 整条带分配（最小分配 ≥ 条带、条带对齐）+ 条带提交记录（或 COW）| 掉电不再产生"坏条带"；无校验 RMW | **改所有写路径**（最深的一坑）|
| **R3 自愈** | 数据校验和（`CRC32` 属性放父指针）+ 读时校验/重建 + scrub（走可达集合）| 能发现并修复静默损坏；能判断"哪块盘坏了" | 每个写路径都要记校验和；父块损坏则校验链断 |
| **R4 运维** | replace / spare / online / offline / status | 恢复冗余 | 依赖 R2/R3 |

**"省事版"**（只想尽快能读）：只做 R0 + R1 —— 卷格式只加 anchor 的 pool 段，映射与重建都放设备层 ——
能读，但**写洞（4）与静默损坏（5）无解**，掉电后半写条带无法判定对错。

## 9. 结论

* **"只差一个映射层"是错觉**。真正横切、会改到每条写路径的三个坑：
  1. **写洞**：原地覆盖 + 无 COW / 事务（ZFS 的根基）；
  2. **无数据校验和**：自愈与"哪块盘坏"的前提；
  3. **分配/记账按 4 KiB chunk**：与条带几何天生不合（窄条带 3× 放大 + 校验 RMW）——
     要改成条带对齐 + 按条带记账。
* **天然优势三条**：`L` 已经是逻辑坐标（映射输入形状对了）、设备接口已抽象（能插 vdev 层）、
  **位图是派生数据**（scrub / resilver 可以只走 live set）。
* 一句话：**做"能带 2 盘故障读"可行（≈ R0 + R1 + 部分 R2/R3）；做"ZFS 级可靠"要引入 COW / 事务，那是重写核心写路径。**

## 10. 待定项

1. **单 vdev 还是多 vdev 池** —— 决定要不要 段末裸 vdev uuid、（多 vdev 才需要）、vdev 范围表。
2. **每盘几份标签**：2 份（头尾各 1）起步，还是 4 份（ZFS 式）。
3. **GUID 宽度**：推荐 **u64**（ZFS 同款，省一半空间）；现有 anchor 的 `uuid` 是 16 B，是否统一。
4. **是否接受"分配 / 记账单位 = 整条带"**（`bit_unit` ≥ 整条带；`chunk` 本身是否也要放大？）。
5. **写安全方案**：条带提交记录 vs COW（前者改动小、后者更接近 ZFS）。
6. **`memmap00…15`（成员表） 上限**：16 项够不够；更大 vdev 用扩展表指针。
