# COW / 对象形态（设计）

> 状态：**设计已定**（v0 **不含快照**）。本文只谈**文件系统设计/格式**层面，不谈实现。
> 相关：[`3-link.md`](3-link.md)（`block_type=3`，链接块）、[`4-file.md`](4-file.md)（四种模式 + 对象形态）、
> [`2-dir.md`](2-dir.md)（目录、条目、链）、[`common.md`](common.md)（不变量）、[`proscons.md`](proscons.md)（P4 位图派生 / P5 无 inode / P8 覆盖写 / P9 提交点、C1）。

## 1. 决定

**COW 是运行时的写策略选择，不是文件的格式属性。**

* **内联（`DATA_TINY`）/ 直接指向（`DATA_PTR`）**：条目里就是内容/段表 → **只能原地写**。
  要 COW 就得先升格成对象形态（§10）。
* **对象形态**（条目只留 `NAME` + 指向**链接块**的稳定引用）：**可以** COW 写，
  但**也允许**原地写（例如它只是为了硬链接共享而存在时）。
* **是否 COW，由本次运行的程序参数决定**（如 `--cow`）。格式里**没有**任何
  "这个文件/这个卷是 COW 的"标记位。

要分清两件不同的事：

| | 是什么 | 谁决定 | 记在哪 |
|---|---|---|---|
| **对象形态** | 结构：条目持**稳定引用** + 一个可作为**提交点**的对象根块 | 创建时决定（或被硬链接 / 首次 COW 写**触发升格**）| **在格式里**（条目里是引用而不是内联段表）|
| **COW 写** | 策略：数据写新块 → 根块一次写换映射 → 提交后释放旧块 | **本次运行的程序参数** | **不在格式里** |

**方向是单向的**：`COW 写 ⇒ 必须对象形态`（否则"换映射"就得改目录块，见 §2）；
反过来 `对象形态 ⇏ COW 写`。

> ⚠️ 两个必须写清的推论：
> 1. **对象形态本身不提供任何保护** —— 一次"不带 `--cow`"的运行照样会原地写它；
>    保护完全来自"**这次运行选了 COW**"。
> 2. **硬链接的文件不会自动 COW**：它只是（因为要共享）呈对象形态；
>    原地写会让所有名字都看到新内容 —— 那本来就是硬链接的语义 ✓，不冲突。
>    要它免疫半写，就跑 `--cow`。

## 2. 它绕开了什么（这是本方案的核心价值）

**P5（"文件就是它的目录条目"）与 COW 根本冲突**：COW 要求"可变的东西住在被**稳定标识**的对象里"，
而 P5 把文件的可变部分（映射、时间）放在**目录条目**里 → 改文件就必然改目录块，
而目录块是"多条目的容器 + 双向链"（[`2-dir.md`](2-dir.md)）→ 粒度放大 × 路径放大。

对象形态把这一串问题**一次绕开**：

```
条目（稳定，永不因文件内容变化而改写）:  NAME + 引用(L) ──► 对象根块 ──► 数据段
                                                              ↑ 原地写，就是提交点
```

* 文件的可变部分全在对象里 → **写文件不碰目录** ✓
* 条目里那个引用是**稳定的**（`L` 在四个方向的伸缩下都不变，[`layout.md`](layout.md)）✓

---

## 3. 写序（提交点）

```
1. 数据写【新块】（分配 → 写 → 置位）
2. 对象根块【一次块写】换掉映射      ← 提交点
3. 提交之后才释放被替换掉的旧块      （与"先解引用后释放"同源）
```

| 崩在哪 | 状态 |
|---|---|
| 1 与 2 之间 | 旧映射仍有效 → **旧版本完整**，新块是垃圾（可回收）✓ |
| 2 之后、3 之前 | 新版本有效，旧块**泄漏**（可回收）✓ |
| 写 2 的中间 | 见 §4 的 A/B 双槽 |

**结论：不需要日志** —— 这正是 P9"一次块写 = 提交点"的思路**从卷级搬到文件级** ✓
（[`proscons.md`](proscons.md) C1"没有日志、没有事务"因此**继续成立**。）

## 4. 对象根块的结构要求

一条硬规则：**根块永不搬家、永不 COW，它是原地写的单块提交点**。

| 要求 | 原因 |
|---|---|
| 根块**只有一块**（永不成链）| 它必须是"一次块写"的原子单元；条目里的引用固定指向它 |
| 带头 CRC + 载荷 CRC | 半写/损坏必须能被检测 |
| 映射 ≤ 单块时：根块自己就是映射 | 简单情形 |
| 映射 > 单块时：根块引用**分片块** | 分片可以 COW（改分片 → 重写根块一次）|
| **抗"根块自身半写"**：块内 **A/B 双槽 + 世代 + 每槽 CRC**，读方取**最新有效**槽 | 媒介的 4 KiB 写未必原子；单槽半写会让文件**无法恢复**（没有旧副本）✓ |

> 双槽的两种放法（待定，见 §10）：① 同一 4 KiB 块内切两半（每槽容量减半）；
> ② 两块一组，条目指向组首，组内用 delta 互指（容量不减，但要防"只写了一半组"）。

---

## 5. 链接块的容量与成链
* 映射 ≤ 单块 → 根块 = 映射。
* 超过 → **根块 + 分片块**：根块是唯一提交点、引用分片；分片可 COW。
* 段数上限与 [`4-file.md`](4-file.md) 是同一个问题（写侧"跨块条目"那条欠账）。

---

## 6. 不做快照 ⇒ 明确**不需要**什么（边界）

| 不需要 | 为什么 |
|---|---|
| **引用计数（refcount）** | 只有一个根 → "位图为 0 = 空闲"**继续成立**（[`1-alloc.md`](1-alloc.md) 的语义不变）；只需补"**提交前不得回收被替换的块**" |
| **"按根解析"的根表 / 根树** | 条目直接存 `L`（直接地址）就够：同一个名字永远解析到**当前版本** |
| 多槽位的卷级根（anchor 的世代仲裁）| 仍按 [`5-anchor.md`](5-anchor.md) 的 I9 规则（撕裂即 `ESTALE`），不需要"取最高世代回退" |

**代价（必须写清）**：**没有多版本** —— 一旦提交并回收，旧内容不可恢复。
> 若将来要快照，要新增一样：**根目录的那个链接块里带一张「编号 → 各代根块」的表**（见 §13 的四步）；
> 那时条目就不能再直接存 `L`，并且"存活/空闲"要变成"对所有保留根都不可达"。

## 7. 设计层代价（明码标价）

| 项 | 代价 |
|---|---|
| **读** | 每次读多一跳：先读对象根块（4 KiB + CRC），再读数据 |
| **写** | 映射必变 → **每次写都要重写根块**（1× 4 KiB 起；成链时还要写分片） |
| **覆盖写（与 P8 相反）** | ②③ 的覆盖写是"纯数据写"；**按 `--cow` 运行时**退化成"**读旧 → 复制到新块 → 重映射**" ✗ |
| **目录** | **完全不动** ✓（这是收益）|
| **空间** | 根块（+ 分片）自身占 chunk |
| **碎片** | COW 产生"刚被替换掉的块"，碎片化比原地写更快 → 与 [`4-file.md`](4-file.md) 的段数上限叠加 |
| **可检查性** | "数据块不得被原地覆盖"是**写入方约定**，事后查不出来；只能查弱化版（§8 的 I10–I12）|

## 8. 不变量（新增）

> **I10 是「运行约定」**（只在按 COW 运行时成立，**不是格式不变量** —— 格式里不记录谁是不是 COW）；
> **I11 / I12 才是可事后检查的格式不变量**。

| # | 内容 |
|---|---|
| **I10**（运行约定）| **按 COW 运行时**，凡被**已提交**的对象根引用的数据块**不得再原地覆盖** —— 保护来自这次运行，不来自格式 |
| **I11** | 同一个对象根引用的各数据段**互不重叠**（防别名）—— **可被事后检查**（事后可检查）|
| **I12** | 对象根引用的块必须存在，且在位图里置位；`NLINK` 与指向该对象的条目数一致（[`3-link.md`](3-link.md)）|

## 9. 与既有原则的关系

| 原则 | 状态 |
|---|---|
| **P4 位图是纯派生数据** | **继续成立** ✓（不做快照 → 仍是"单个根的可达集合之补集"）|
| **P5 没有 inode** | **让出一半**：对选了对象形态的文件，"文件就是它的目录条目"不再成立（可变部分住对象里）；②③ 仍成立 |
| **P8 范围读写/覆盖写便宜** | 对 ②③ 永远成立；**按 `--cow` 运行时**不成立（覆盖写 = 新块 + 提交）|
| **P9 提交点 = 一次块写** | **继续成立**，只是提交点从"目录块"变成"**对象根块**"|
| **C1 没有日志、没有事务** | **继续成立** ✓ —— 本方案的价值正是"不引入日志也能得到不覆盖 + 原子提交" |

## 10. 升格路径与命名

**升格**（②③ → 对象形态）：与 copy-on-link 同一套机制。
触发：**本次运行带 `--cow` 且文件还不是对象形态**，或第一次被硬链接。崩在中途 = 新链接块已写但没人指 → 泄漏 ✓（先占位后引用）。
**命名（已定）**：
* `block_type=3` = **链接块**（见 [`3-link.md`](3-link.md)；块类型表与 `BT_NAME[3]` 都叫 `link`）✓
* 条目指向它的属性 = **`DATA_OBJECT`**（`0x32`，**2 jump**）✓
* §8 的 I10–I12 与 [`3-link.md`](3-link.md) 的检查清单合并。

## 11. 待定项

1. **`--cow` 的作用范围**：单文件（要逐个文件给）/ 整卷（一次覆盖所有写路径）。格式里不记录，所以这是纯粹的运行约定。
2. **根块 A/B 双槽的放法**：块内切两半（容量减半）还是两块一组（容量不减）。
3. **根块 + 分片的具体布局**：根块里放什么（分片引用 / 段数 / 总长），分片里放什么。
4. **`TMODIFY` 住哪**：链接块里（与硬链接一致）。
5. **要不要一个反向开关**（如 `--no-cow`：即使对象形态也强制原地写）。

## 12. 根目录对象与原子性分层
* **根目录也可以用对象形态**：anchor 的 `roottype = 2` + `rootioff` → 根的**链接块**（载荷是
  内容块表）✓ `mkfs` 建议**默认产出对象形态的根**（`--root-chain` 可切回链式 `roottype = 1`）。
  这样"改根目录里一个条目"的提交点就是根的链接块，**不进 anchor** ✓
* **原子性分层**（很重要，别混淆）：

  | 级别 | 由谁保证 | 覆盖范围 |
  |---|---|---|
  | **对象级** | 链接块内的 **A/B 双槽 + 版本号** | 一个文件 / 一个目录的内容提交是原子的 ✓ |
  | **卷级** | head / tail anchor **必须一致**（[`5-anchor.md`](5-anchor.md)）| 配对与几何不猜；**但不提供"跨多个对象的一次性提交"** ✗ |
* 所以 v0 的 COW 语义是：**每个对象各自原子**，**没有跨对象事务、没有快照** ✓
* 快照的前提是"**根表**"：根目录的链接块载荷里带一条 `编号 → 各代根块` 的属性 ✓

## 13. 快照要补齐的四步（设计方向）

快照 ≠ "把位图 object 化" ✗。它要**四件事一起到位** ✓（前三件是"能共享"，第四件是"能回收"）：

| # | 要什么 | 现状 | 说明 |
|---|---|---|---|
| ① | **多世代根** | ✗ | 一个入口能指向"那一刻的整棵树"：根目录的链接块里的一张 `编号 → 各代根块` 表✓；anchor 侧要有"当前根"，`gen` 已经能当世代号用 ✓ |
| ② | **被历史引用的东西都不原地覆盖**（COW）| 文件 ✓ / 目录 ✗ / 位图 ✗ | 文件靠对象形态 ✓；**目录靠 `DIR_OBJECT`** ✓；位图见 ③ |
| ③ | **分配信息可版本化** | ✗ | 扁平位图**表达不了"按世代的空闲"** ✗ ⇒ 要么**按世代增量**（ZFS 的 spacemap ✓）要么**引用计数**（btrfs / XFS ✓）|
| ④ | **延迟释放** | ✗ | 删掉的块不能立刻清位 ✓（别的世代可能还引用 ✓）⇒ 记进**按 `gen` 的待释放队列**，等"最老活跃根"过去再清 ✓（ZFS 的 deadlist）|

**目录级 COW 单独说**（这一件最容易 ✓）：

* 升格成 `DIR_OBJECT` 之后，"改目录里一个块" = 写新块 + 改表里一项 ⇒ **一次换根** ✓；
* **父目录不用改** ✓（父条目持的是稳定引用 ✓）⇒ 改动不会沿目录树往上传播 ✓；
* 配套三件：**`DIR_OBJECT` 写侧** ✗、"dir 块只写新块" ✓、旧块回收（通用头的 `refcount` / `owner_gen` ✓）。
* 表超过一块时**不要用链** ✗（会把"邻居耦合"带回来）⇒ 直接上**树**（键用 `NAME_HASH` ✓）。

**位图是最特殊的一环** ✓：它**不像文件 / 目录那样"COW 一下就版本化了"** ✗ —— 它是**派生数据**（I3 ✓），
真正的权威是"**引用结构 + 世代信息**" ✓，位图只是它的**缓存** ✓。所以：

* **短期**（先让快照跑起来）：扁平位图 + **按 `gen` 的延迟释放队列** + **多世代根** ✓（不必动位图结构 ✓）；
* **长期**：`bitmap_OBJECT`（按世代增量 / 引用计数 ✓），并且**始终保留"从引用结构重建位图"** ✓
  （`fsck` / `optimize` ✓）。

> **两个要一起定的问题**：① **自举** —— 分配器自己也占块，它的块从哪来（预留池 / 自举例外 ✓）；
> ② **写放大** —— 分配器几乎每次写都变 ⇒ COW 化后每次提交多一条路径拷贝 ✗ ⇒ 用"追加式块 + 内存聚合"缓解 ✓。
> 完整讨论见 [`3-link.md`](3-link.md) 的结构可插拔一节（尤其分配器层 ✓）。
