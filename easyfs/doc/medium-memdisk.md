## 1. 它是什么

一块**按字节访问的内存**（启动时分配），上面跑**同一套 4 KiB 块格式**：

* 同一个建卷 / 校验流程 ✓、同一套 anchor / 位图 / 目录 / 链接块 ✓；
* 对格式层来说它只是"能按偏移读写的载体" ✓ —— **不需要为内存改格式一个字节** ✓；
* 内容**不落盘** ✓：进程结束即消失 ✓（除非你自己把字节存下来 ✓）。

> 这一条本身就是"载体抽象"的验证 ✓：**卷格式不关心载体是磁盘、文件还是内存** ✓。

---

## 2. 用途

| 用途 | 为什么合适 |
|---|---|
| **单元测试 / CI** | 快（无磁盘 IO）、干净（每次都是新卷）、可并行 |
| **演示** | 一条命令就能起一个可用卷 + 网络访问（见 [`../python/README.md`](../python/README.md)）|
| **嵌入式 RAM 区** | 上电可用的"参数区 / 暂存区"（形态见 [`usecase-memorymanage.md`](usecase-memorymanage.md)）|
| **只读镜像的造法** | 先在内存里建卷 + 放文件，再把字节烧进 ROM —— 格式与盘上完全一致 |
| **掉电安全测试** | 人为"拔电"（扔掉内存）⇒ 验证 dirty 重建、泄漏只增不减 |

---

## 3. 语义与边界

| 项 | 行为 |
|---|---|
| 掉电 | **全丢**（没有落盘）|
| 容量 | **固定** —— 没有"设备"可扩 ⇒ 要更大就重建 |
| 持久化 | 不提供 ⇒ 要持久请用文件 / 虚拟磁盘 |
| 并发 | 只在**本进程内**（没有锁）|
| 与 swap / tmpfs | 无关 —— EasyFS 不是操作系统组件 |
| 残留 | 进程退出即释放（不会留一个"脏"卷给别人）|

---

## 4. 和其它载体对比

| 载体 | 会不会丢 | 容量 | 典型用途 |
|---|---|---|---|
| **内存**（本篇）| 进程结束即丢 | 固定 | 测试 / 演示 / RAM 区 |
| 文件（`.img`）| 持久 | 可变 | CI / 小卷 |
| 虚拟磁盘（`.vhd` / `.vmdk`）| 持久 | 可变 | 分发 / 模拟真盘 |
| 真盘 / 分区 | 持久 | 固定 | 生产 |

四种载体的**卷格式完全一样** ⇒ 可以把"内存里造好的卷"原样写成文件 / 烧进 ROM。

## 6. 待定项

1. **两层载体**（内存里跑、定期落盘）要不要做 —— 现在只支持"选一个载体"；
2. 内存卷的**容量口径**：只给字节数，还是也认块数；
3. **只读载体**（ROM / flash 只读区）要不要单独支持 —— 只读载体上写应当报错，这需要明确成契约。
