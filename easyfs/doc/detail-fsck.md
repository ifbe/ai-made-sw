# 校验规范（detail · fsck）

> **契约文档**：规定 `fsck` **检查什么**、**多严重**、**能不能修** ✓ —— 两份实现必须得出同样的结论 ✓。
> 依据是卷里的**引用结构**（真相 ✓），不是位图（派生数据 ✗）。
>
> 相关：[`detail-common.md`](detail-common.md)（块头、不变量）、[`detail-layout.md`](detail-layout.md)（区域几何、`L`）、
> [`5-anchor.md`](5-anchor.md)（anchor 一致性 I9）、[`1-alloc.md`](1-alloc.md)（I7′、dirty 重建）、
> [`2-dir.md`](2-dir.md)（属性与条目规则）、[`3-link.md`](3-link.md)（`NLINK`、泄漏）、
> [`4-file.md`](4-file.md)（四种模式、段）、[`6-bad.md`](6-bad.md)（坏块）、
> [`feature-snapshot.md`](feature-snapshot.md)（保留世代 I13–I16）。

---

## 1. 定位与两条原则

* `fsck` 有**两种模式** ✓：**只读检查**（默认 ✓，只报告 ✓）与**显式修复**（要人/脚本明确要求 ✓）；
* 原则一：**只信卷里记的** ✓ —— 卷说自己在哪、多大、根在哪，就以它为准 ✓（不拿设备大小去猜 ✗）；
* 原则二：**从引用结构出发** ✓ —— 可达集合由"根 → 目录 → 引用"算出来 ✓；位图只用来**对照** ✓，
  位图坏了就**重建** ✓，而不是反过来相信位图 ✗。

> 这条决定了整个规范的形状 ✓：**位图的一切问题都是"可重建"级别** ✓，
> 而**引用结构的问题才是"卷坏了"级别** ✓。

## 2. 检查项清单

### 2.1 块头（每个"有头的块"都要查）

| # | 检查 | 依据 |
|---|---|---|
| A1 | `magic` 是 `easy` 前缀，且**等于该类型应有的魔数** | [`detail-common.md`](detail-common.md) |
| A2 | `block_type` 是已知值（0–6）；`0` = 损坏 | 同上 |
| A3 | `header_bytes` / `payload_len` 不越出块自身（元数据块 = 4 KiB；位图块看 `block_bytes`）| 同上 |
| A4 | `header_crc32` 覆盖 `[0, header_bytes)` 正确（**anchor 的对应物是 tag `hdrcrc`**，见 B1）| 同上 |
| A5 | `flags` 的保留位为 0；`payload_crc` 有效时校验载荷；**dir / link 必须启用载荷 CRC** | 同上 |
| A6 | 链接块的 `prev_delta` / `next_delta` 解算后**不越界** | 同上 |

### 2.2 anchor（head / tail 各一份）

| # | 检查 | 依据 |
|---|---|---|
| B1 | **至少一份** anchor 可解析且 `hdrcrc` 正确；另一份缺失 / CRC 坏 ⇒ 可由好的那份重建 | [`5-anchor.md`](5-anchor.md) |
| B2 | tag 表齐全、顺序合法、保留 tag / 保留字段为 0 | 同上 |
| B3 | `poolcrc`（有 pool 段时）正确 | 同上 |
| B4 | `peer` 互指；**I9 的关键字段一致**（几何 + `gen` + 根 + 分配结构）| 同上 |
| B5 | `reglen` / `dlolog` / `chunk` 自洽：`chunk` 是 2 的幂且 ≤ 4096 ✓，`reglen` 是 `chunk` 的整数倍 ✓，`dlolog` 与 `chunk` 对齐 ✓ | [`detail-layout.md`](detail-layout.md) |
| B6 | `roottype` 合法；`rootioff` 解算后**在 `[data_lo, data_hi)` 内且按 `chunk` 对齐**（`roottype = 0` 时跳过）| [`5-anchor.md`](5-anchor.md) |
| B7 | `allotype` 合法；`alloioff` 同 B6；`allocnum` / `allosize` 与实际分配结构一致 | [`1-alloc.md`](1-alloc.md) |
| B8 | `policy` 是已知 id；`stateflg` 的保留位为 0 | [`5-anchor.md`](5-anchor.md) |
| B9 | `uuid` 两份一致；空卷时 `roottype = 0` | 同上 |

### 2.3 分配结构

| # | 检查 | 依据 |
|---|---|---|
| C1 | 区域链按 `logical_start` **非递减**（同起点时父在前）| [`1-alloc.md`](1-alloc.md) |
| C2 | 每个子区域落在父区域的**若干完整单位**内（可跨多个，不占半格），且父位图那些位已用 | 同上 |
| C3 | **叶区域并集 = `[data_lo, data_hi)`**，无洞无重叠 | 同上 |
| C4 | **同层**区域之间不重叠；任何区域不越出卷（父 / 子按包含关系，不算重叠）| 同上 |
| C5 | `bit_unit` 是 2 的幂，且是 `chunk` 的整数倍 | 同上 |
| C6 | 每个分配结构块**自己在位图里置位** | 同上 |
| C7 | 块内位图的位数与区域跨度一致 | 同上 |

### 2.4 目录

| # | 检查 | 依据 |
|---|---|---|
| D1 | 链的 `seq` 单调；`prev` / `next` **互相对称**；链不死循环 | [`2-dir.md`](2-dir.md) |
| D2 | `payload_len` 与属性流一致（恰好走到 `payload_len`）；**属性不跨块**；块尾 slack 不参与解析 | 同上 |
| D3 | 属性类型合法（`0x00–0x0D` = 损坏；未知高号可跳过）；`CRC32` 若存在**必须在末位** | 同上 |
| D4 | 条目属性组合合法（`NAME` 必有；`DATA_TINY` 最多一条、`DATA_PTR` 可多条；`DIR_PTR`、`DATA_OBJECT` 与内容属性三者互斥）| 同上 |
| D5 | 同一目录内 `NAME` 不重复 | 同上 |
| D6 | `PADn` / `PAD1` 可填充条目之间的空洞；**不做条目分隔、不覆盖内容属性** | 同上 |
| D7 | 一个 dir 块只被**一条链或一张内容块表**引用（同一时刻不共享）| 同上 |

### 2.5 文件与链接块

| # | 检查 | 依据 |
|---|---|---|
| E1 | 四种模式的组合合法（空 / 内联 / 直接指向 / 指向链接块）| [`4-file.md`](4-file.md) |
| E2 | `DATA_PTR` 各段落在数据区、**互不重叠**（I11）、段和 = 文件大小（`DATA_TINY.len + Σ size`，不单独存）| 同上 |
| E3 | 每段起点按 `chunk` 对齐；`size` 是**真实字节数**（可非 `chunk` 整数倍，末段尤其如此）| 同上 |
| E4 | `DATA_OBJECT` 指向的块 `block_type = 3`；链接块的表项全部有效 | [`3-link.md`](3-link.md) |
| E5 | 链接块的 `NLINK` **等于指向它的条目数** | 同上 |
| E6 | 链接块的映射项与 E2 / E3 同规则 | 同上 |
| E7 | 硬链接不允许指向目录、不允许指向软链接 | 同上 |

### 2.6 可达性与位图

| # | 检查 | 依据 |
|---|---|---|
| F1 | 从根扫出**可达集合 `R`**（目录链 → 条目 → 内容，含软链接目标）| [`4-file.md`](4-file.md) |
| F2 | `R` 里每个块都在位图里**置位**；否则 = **悬空引用** ✗ | [`1-alloc.md`](1-alloc.md) |
| F3 | 位图里已用但**不可达** = **泄漏** ✓（可回收 ✓；**bad 块 / 分配结构自身除外**，见 F4 / C6）| 同上 |
| F4 | 坏块位**必须恒为 1**（位图重建时也要重新置 1）| [`6-bad.md`](6-bad.md) |
| F5 | 一个块**只承担一种角色**（数据 / 目录 / 链接块 / 分配结构）| [`detail-common.md`](detail-common.md) |
| F6 | 裸数据块**没有头**、只能被父指针确认（不参与 A 类检查）| [`4-file.md`](4-file.md) |

### 2.7 快照（有保留世代时才查）

| # | 检查 | 依据 |
|---|---|---|
| G1 | I13：根表项 `gen` 唯一，且都 ≤ anchor 的 `gen` | [`feature-snapshot.md`](feature-snapshot.md) |
| G2 | I14 / I15：每个保留世代的根可达，且其可达集都在位图里置位 | 同上 |
| G3 | I16：待释放队列里的块**不得**被任何保留世代可达 | 同上 |

## 3. 严重性分级（三档）

| 级别 | 含义 | 例子 |
|---|---|---|
| **FATAL** | **拒绝挂载**（读写都不行 ✓）| 两份 anchor 都不可用（magic / `hdrcrc` 都错）✓、I9 不一致 ✓、设备比卷小（`dev.size < reglen`）✓、根不可读 ✓、分配结构无法解析 ✓ |
| **ERROR** | 卷**已损坏**，但可能仍能只读读出部分 ✓ | 悬空引用 ✗、段重叠 ✗、`NLINK` 不符 ✗、属性非法 ✗、链断裂 ✗ |
| **WARN** | **可修**或**可忽略** ✓ | 泄漏块 ✓、单份 anchor 缺失 / CRC 坏（可由另一份重建）✓、位图脏 / 过期 ✓、位图与可达集不一致（可重建 ✓）、坏块位被清 ✓ |

> 判定顺序很重要 ✓：**先判 FATAL** ✓（能挂载吗 ✓），再判 ERROR ✓（内容还对吗 ✓），最后 WARN ✓（空间账对不对 ✓）。

---

## 4. 修复策略

1. **默认不修** ✓：只读检查只报告 ✓；修复必须是**显式**动作 ✓；
2. **修派生数据优先** ✓：位图 / 可达集这类可以**整个重建** ✓ ⇒ 先重建 ✓，再看 ERROR 还剩多少 ✓；
3. **绝不猜内容** ✗：悬空引用 / 段重叠这类**无法安全重建** ✓ ⇒ 只能报告 + 隔离（把可疑项挂到"丢失+发现"目录 ✓）✓；
4. **修复也要满足"只泄漏不损坏"** ✓：每一步只做"写新块 + 换引用" ✓；崩在中途 ⇒ 旧状态仍完整 ✓；
5. **修完必须再跑一遍只读检查** ✓（修复自证 ✓）；线上场景建议**先在副本上修** ✓。

---

## 5. 不检查什么

| 不查 | 为什么 |
|---|---|
| 文件内容是否正确 | 那是应用的事 ✓（我们只保证"读到的就是写进去的" ✓，以及可选的 `CRC32` ✓）|
| 时间戳是否"合理" | 只检查字段宽度与类型 ✓，不判断时间对不对 ✓ |
| 权限 / 属主 | 格式里没有 ✓ |
| 分区表 / 虚拟磁盘元数据 | **卷格式之外** ✓（见 [`medium-parttable.md`](medium-parttable.md) / [`medium-virtualdisk.md`](medium-virtualdisk.md)）|
| 未分配的块里有什么 | 不重要 ✓（可能残留旧数据 ✓）|

---

## 6. 每条结论该带什么信息

一条检查结论至少要能回答：**哪个块**（卷内偏移 ✓）、**谁引用它**（父指针 ✓）、**期望 vs 实际** ✓、
**严重性** ✓ —— 否则人没法判断要不要修 ✓。

---

## 7. 待定项

1. `fsck` 要不要支持"**只查某一部分**"（只看 anchor / 只看根子树 ✓）；
2. 泄漏块的**自动回收**要不要做成默认行为 ✓（现在偏向"只报告 ✓"）；
3. "丢失+发现"目录的命名与落点 ✓（要不要标准化 ✓）；
4. 大卷的**并行检查** ✓（按区域切分 ✓）与内存上限 ✓。
