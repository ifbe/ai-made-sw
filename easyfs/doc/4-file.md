## 1. 四种模式总览

**看"内容在哪"，就看属性的"跳数"** —— 条目里放什么属性，决定跳几次才拿到数据。
（**跳数是"文件内容"的概念**；软链接的 `SYMLINK_*` 不按跳数描述，见 §9。）

| 模式 | 属性组合 | 跳数 | 内容在哪 | 定位需要什么 | 占分配单位 |
|---|---|---|---|---|---|
| **① 空文件**（只有名字） | `NAME` `[TMODIFY]` | — | 没有内容 | — | 0 |
| **② 内容在条目里** | `NAME` `DATA_TINY` `[TMODIFY]` | **0 jump** | **目录条目内**，≤255 B | 这条属性本身 | **0** |
| **③ 目录直接指向** | `NAME` `DATA_PTR × n` `[TMODIFY]` | **1 jump** | 裸数据块 | 属性本身（**自相对 delta**） | 每段 |
| **④ 目录指向对象** | `NAME` `DATA_OBJECT` `[TMODIFY]` | **2 jump** | 链接块 → 裸数据块 | `L`（链接块地址）→ **链接块里的段表** | 每段 + 链接块 |
| *（对照）目录* | `NAME` `DIR_PTR` `[TMODIFY]` | — | dir 块链 | 属性本身 | 每块 |

* **④ 的属性只有一条** —— 一个文件只有一个对象，所以**没有 `× n`**；③ 是内联段表，**可以多条** ✓
* **④ 的条目里没有数据属性、也没有时间属性**（映射与时间都在链接块里）—— 见 [`3-link.md`](3-link.md)
* ④ 有两种用途：**硬链接**（多名字共享）与 **COW**（[`cow.md`](cow.md)）。
  **是否 COW 由运行参数决定**（如 `--cow`），格式里没有标记位

**谁产生哪种**：

* 写入方按内容长度**自动选 ①②③**（`create(name)` → ①；`create(name, data=…)` 且 ≤255 B → ②；
  更长 → ③）。v0 的 `_encode_entry()` 产出的**指针只有 `DATA_PTR`**（内容 ≤255 B 时用 `DATA_TINY`）。
* **④ 的读取方与 fsck 必须支持**（解析、范围读、`_walk_used`、`rebuild_bitmap` 都走同一套）；
  写侧在**按 `--cow` 运行时**由"升格"产生（[`3-link.md`](3-link.md)）。
* 模式**可以混用**：同一文件里 `DATA_TINY` 与指针属性都能共存（§4）。

## 2. 逐模式

### ① 空文件（只有名字）

```
40 05 61 2E 74 78 74            NAME "a.txt"
43 04 <u32>                     TMODIFY（可选）
```

* `size = 0`，不占任何分配单位 ✓ —— "不占 inode、不占块的空文件"。

### ② 超小文件（内容存在目录里）

```
40 05 61 2E 74 78 74                     NAME "a.txt"
30 0C 48 65 6C 6C 6F 20 77 6F 72 6C 64 21 DATA_TINY len=12（内容就在这儿）
```

* `DATA_TINY` 的**值就是内容**，上限 **255 B**（属性 `len` 是 1 字节）。
* **占 0 个分配单位** —— 内容住在目录块里（[`2-dir.md`](2-dir.md)）。

### ③ 目录直接指向文件（物理偏移）

```
40 05 76 2E 62 69 6E             NAME "v.bin"
31 0C <i64 delta> <u32 size>     DATA_PTR 段1
31 0C <i64 delta> <u32 size>     DATA_PTR 段2
```

* 值 = `{i64 delta}{u32 size}`，12 B；`delta` 的基准是**存放该属性的块**（[`common.md`](common.md)）。
* 段表**可以多条**（`× n`），按属性出现顺序拼成文件内容。
* `size` 是**这段文件数据的真实字节数**，不是"分配到的空间"（最后一段可能只用了半块）。

### ④ 目录指向对象（2 jump）

```
40 0A 76 2E 62 69 6E 2E 6F 62 6A        NAME "v.bin.obj"
32 08 <i64 L>                            DATA_OBJECT → 链接块
```
* 条目里**只有** `NAME` + `DATA_OBJECT`（时间由链接块持有，条目里没有）。
* **跳两次**：条目 → **链接块**（`block_type=3`）→ 裸数据块。
  链接块里放的是**段表**（`DATA_PTR` 等，delta 基准 = **链接块自己**）与 `NLINK` / 时间。
* 好处：**映射可以整体替换**，而条目里的引用是**稳定的**（`L` 不变）→ 这是
  **COW**（[`cow.md`](cow.md)）能"只换映射、不动目录"的前提。
* 同一个对象可以被**多个名字**引用（硬链接，`NLINK` ≥ 2）—— 见 [`3-link.md`](3-link.md)。

## 3. 为什么不保留 `DATA_PTR_LOGICAL`（已退休）

曾经有一个 `DATA_PTR_LOGICAL`：一种**按卷逻辑坐标 `L` 寻址**的指针（值 `{i64 L}{u32 size}`，
与 `DATA_PTR` 只差"地址怎么写"）。它**已退休** —— 那个槽位已归还保留区。理由：

* 它和 `DATA_PTR` 是**同一件事的两种地址写法**（都是内联段表），只需要一种；
* 它想解决的问题（"引用不随宿主块搬家而失效"）现在由 **④ 对象形态**更彻底地解决：
  `DATA_OBJECT`（`0x32`）指向一个**位置稳定**的链接块，且对象里的段表**可以整体替换**
  —— 这正是 COW（[`cow.md`](cow.md)）的前提；
* 它一直是 `[待定]`，写入方从未产出。

> **`L` 这个坐标本身仍在用**：[`layout.md`](layout.md) 定义它，`DATA_OBJECT` 的值就是 `L`；
> 链接块**内部**的段表用 self-relative delta（基准 = 链接块自己）。

## 4. 逻辑布局与"混用"

```
[0, tiny_len) ← DATA_TINY（0 或 1 条）
[tiny_len, tiny_len + Σ size_i) ← 各 DATA_PTR，按属性出现顺序
                                         （对象形态则看链接块里的段表）
```

* **文件大小是派生值**：`size = tiny_len + Σ size_i`，卷里**不存** `size` 字段 ✓
  （所以条目形状与大小天然一致，不会出现"大小与映射对不上"）。
* **无缝无洞**：各段必须首尾相接、并集 = `[0, size)` ✓
* `DATA_TINY` 与指针属性**可以共存**；同一文件里 `DATA_TINY` 之后接多段是常态 ✓
* ④ 与 ①②③ **互斥**（对象形态的条目里不放内容属性）。

## 5. 读写语义：范围读 / 范围写

**范围读** `read_range(ent, offset, length)`：

* 逻辑布局是**顺序**的 → 先按段累加逻辑位置跳过 `offset` 之前的段，
  再只读真正相交的那几段，越过结尾立刻停 → **不会为了读 4 KiB 去碰整个文件**。
* 代价：定位要扫一遍属性（段数少时就是几十次循环）。

**范围写 / 覆盖写**：

* 段内覆盖是**纯数据写**（直接写进 `DATA_PTR` 的段，不碰元数据）—— 这是 P8 便宜的直接原因。
  ⚠️ 只对 ②③ 成立；**按 `--cow` 运行时**，对象形态要"读旧 → 复制到新块 → 重映射"。
* **越过 EOF 的写 = 追加**：先分配新段并写入（**先占位**），再把新 `DATA_PTR` 加进条目
  （**后引用**）—— 崩在中间只是泄漏（[`1-alloc.md`](1-alloc.md)）。
* 追加会让条目变长；单块放不下时的处理见 §8（`EFRAG`）。

## 6. 字节级示例

一个"12 B 内联 + 50000 B 段"的文件：

```
40 05 6D 69 78 2E 62 69 6E                     NAME "mix.bin"       11
30 0C 48 65 6C 6C 6F 20 77 6F 72 6C 64 21      DATA_TINY len=12     14
43 04 5F 12 34 56                              TMODIFY              6
31 0C <i64 delta> <u32 50000>                  DATA_PTR             14
```

* 读 `[0, 12)` → 来自 `DATA_TINY`；读 `[12, 50012)` → 来自那一段。
* **读 `[10, 20)` 会跨两者**：前 2 字节来自 `DATA_TINY`，后 8 字节来自数据段 ✓
  （范围读必须能跨段拼接，这是 §5 的实现要点）。

**④ 同样内容、改走对象**：条目换成 `NAME` + `30 08 <i64 L>`；
段表与 `size` 都在链接块里（`DATA_PTR` / `DATA_TINY` + `NLINK`），
条目不再随内容变化而改写 ✓

## 7. fsck 检查清单（文件层）
1. `size` = `DATA_TINY.len + Σ(size of DATA_PTR)`（或链接块里的段表）；**必须能算出来**。
2. 属性组合合法：`DATA_TINY` 最多一条；`DATA_PTR` 可多条；`DATA_OBJECT` 恰好一条（一个文件一个对象）；
   ④ 与内容属性**互斥**。
3. **无缝无洞**：段按顺序首尾相接，并集 = `[0, size)`。
4. 各段落在数据区内、不越界、**互不重叠**（重叠 = 别名，最危险的一类）。
5. `DATA_TINY` ≤ 255 B。
6. `DATA_PTR` 的 `delta` 换算出的物理地址必须 chunk 对齐（v0：`bit_unit == chunk`）。
7. `DATA_OBJECT` 的 `L`（以及链接块内段表的 delta）：换算/校验同样要落在数据区内（I8）。
8. 条目里不出现 `DATA_PTR` / `DATA_OBJECT` 指向 anchor 区或位图链自己的块（那属于 carve-out，
   见 [`1-alloc.md`](1-alloc.md)）。
9. 软链接相关检查见 §9。

## 8. 上限

| 项 | 值 |
|---|---|
| `DATA_TINY` | 255 B（格式硬上限；策略阈值可配 0..255）|
| 单个 `DATA_PTR` | 一段连续空间，`size` 是 u32 → 单段 ≤ 4 GiB−1 |
| 段数 | **格式无上限**（条目可顺链跨块）；**写侧 v0** 单块 ≤ 4032 B → 约 **287 段** |
| 超了怎么办 | 报 `EFRAG` = 写侧待实现，不是格式限制（[`2-dir.md`](2-dir.md)）|
| 链接块的映射 | 超过一块 → 成链（根块 + 分片），见 [`3-link.md`](3-link.md) |
| 名字长度 | ≤255 字节（[`2-dir.md`](2-dir.md)）|

## 9. 软链接（内容的三种编码）

软链接**没有数据属性流**：内容就是"目标路径字符串"，用**专用属性**表达（**不按跳数描述**）：

| 类型 | 值布局 | 说明 |
|---|---|---|
| **`SYMLINK_TINY`**（`0x20`）| `{path}`（≤255 B）| 目标路径**就在属性里** |
| **`SYMLINK_PTR`**（`0x21`）| `{i64 delta}{u32 size}` | 目标放**数据块**里，delta 寻址 |
| **`SYMLINK_OBJECT`**（`0x22`）`[待定]` | `{i64 L}{u32 size}` | 目标放**数据块**里，`L` 寻址 |

* 三种类型**对应 ①②③ 的内容编码**（模式①"空"对软链接**不合法**：空目标要拒绝）。
* `size` = 目标路径长度（派生值）；`read()` 一个软链接 = 读出目标路径字符串（`readlink` 语义），
  所以**不认识软链接的客户端会把它当小文件**，行为也说得通。
* **解析、循环检测、深度/总长上限都在调用方**：格式只存字符串，不解析、不校验。
* ⚠️ **解析 + 打开不是原子的**（TOCTOU）：真文件系统靠内核在 `open` 里锁目录，我们没有锁概念。
* 代价：映射语义在软链接路径上**有第二份实现**（读、fsck、位图重建各覆盖一遍）—— 见 §10 第 1 条。
* **不允许硬链接到软链接**（创建时 `ENOTSUP`；fsck 检查，见 [`3-link.md`](3-link.md)）。
**fsck**：`SYMLINK_TINY` 至多一条；`SYMLINK_*` 与普通内容属性**不得混用**；目标路径非空。
