# 快照（feature · snapshot）

> **设计文档**：要不要快照由**运行参数**决定（和 COW 一样 ✓）；**代码做到哪一步**见
> [`../python/README.md`](../python/README.md) ✓。
>
> 相关：[`feature-cow.md`](feature-cow.md)（COW 与对象形态）、[`3-link.md`](3-link.md)（链接块、结构可插拔）、
> [`1-alloc.md`](1-alloc.md)（位图、延迟释放）、[`5-anchor.md`](5-anchor.md)（anchor 的世代仲裁）。

---

## 1. 快照要解决什么

**一句话**：让「**某一刻的整棵树**」在之后仍然可达 ✓ —— 写新内容不会毁掉旧内容 ✓。

**不是**"把位图 object 化" ✗ —— 位图是**派生数据**（I3 ✓），真正的权威是
「**引用结构 + 世代信息**」✓，位图只是它的缓存 ✓。

---

## 2. 三个概念（先钉住）

| 名词 | 含义 |
|---|---|
| **世代（`gen`）** | 卷级的**单调提交计数** ✓（anchor 里已经有 ✓）。每次原子提交 +1 ✓ |
| **保留世代** | 被某个快照**钉住**的 `gen` ✓ —— 这一代的根必须一直可达 ✓ |
| **根表** | `gen → 那一代的根块` 的映射 ✓ —— 它**住在根目录的那个链接块里**（载荷本来就是 TLV 属性流 ✓）|

> **根表不进 anchor** ✓：anchor 的 `rootioff` 只能指**一个**根（`roottype = 1` 链式 / `2` 链接块 ✓）。
> 把「多代」放进**根的那个链接块**里 ⇒ anchor 仍然只指它 ✓ ⇒ 换根时 anchor 的写法完全不变 ✓，
> 也不用为快照新增字段或新的 `roottype` 值 ✓（`3`–`255` 保留着，暂时用不上 ✓）。

---

## 3. 一次快照 = 记根 + 记表 + 提交

1. **记根**：把**当前这一代的根**（根目录的内容块表入口）记下来 ✓ —— 之后的写按 COW 产生新根块，
   **旧根块不覆盖** ✓（前提：根目录是对象形态 `DIR_OBJECT`，见 §4 ②）；
2. **记表**：在**根目录那个链接块**的**根表**里加一项 `(gen = 当时的 gen, 根块 = 这一代的根块)` ✓；
3. **提交**：根链接块是**原地写的单块提交点**（[`feature-cow.md`](feature-cow.md) 的"对象根块的结构要求"一节），anchor 不变 ⇒ 一次块写 ✓。

**崩溃点**只有根链接块那一次写：A/B 双槽保证读到的是**旧槽**（还没有这个快照）或**新槽**
（快照已记）✓，不会出现半个根表 ✓。

**删快照 / 回滚**：把根表里那一项去掉 ✓ —— 但**不能**立刻释放它的块 ✗（见 §6 延迟释放 ✓）。

---

## 4. 四项必须一起到位（缺一项都会坏 ✓）

| # | 要什么 | 为什么 / 靠什么 |
|---|---|---|
| ① | **多世代根** | 根表（§2）✓ —— 一个入口能指向"那一刻的整棵树" ✓ |
| ② | **被历史引用的东西不原地覆盖** | 文件靠对象形态 ✓；**目录靠 `DIR_OBJECT`** ✓（目录级 COW 的提交点 ✓）|
| ③ | **分配信息可版本化** | 扁平位图表达不了"按世代的空闲" ✗ ⇒ 短期靠**延迟释放队列** ✓、长期按世代增量 / 引用计数 ✓ |
| ④ | **延迟释放** | 删掉的块不能立刻清位 ✓（别的世代可能还引用 ✓）|

---

## 5. 存活判定（这条不改，快照必坏 ✗）

| 场景 | 没有快照时 | 有快照时 |
|---|---|---|
| 块是否空闲 | 从**唯一根**可达 ⇒ 不空闲 | **从所有保留世代都不可达** ⇒ 才空闲 ✓（bad 块恒不空闲）|
| `fsck` | 从根扫一遍 | 从**每个保留世代**的根各扫一遍，合并 ✓ |
| 位图重建 | 同上 | 同上，并把"待释放队列里尚未到期"的块视为**占用** ✓ |
| `optimize` | 回收"全空子区域" | 只在**所有保留世代里都空**的区域才可回收 ✓ |

---

## 6. 延迟释放（按 `gen` 的待释放队列）

* 释放一个块时**不立刻清位** ✓，而是记一条 `(块, 释放时的 gen)` ✓；
* 当「**最老的保留世代**」已经越过那条记录的 `gen` ✓ ⇒ 才真正清位 ✓；
* 队列本身是**派生数据** ✓（可由"引用结构 + 保留世代集合"重建 ✓）⇒ 允许丢 ✗、允许过期 ✓；
* 摆放位置见 §10 待定项 ✓。

---

## 7. 与既有机制的关系

| 机制 | 快照下的变化 |
|---|---|
| **P4 位图是派生数据** | **继续成立** ✓（待释放队列也是派生的 ✓）|
| **P9 提交点 = 一次块写** | **继续成立** ✓ —— 提交点还是"根那个链接块的一次写" ✓（根表就在里面 ✓）|
| **C1 没有日志、没有事务** | **继续成立** ✓ —— 快照只加"引用 + 延迟释放" ✓，不引入日志 ✓ |
| **I9 head / tail 一致** | 不变 ✓（anchor 仍是那个仲裁点 ✓）|
| **`resize`** | 有保留世代时，缩容的腾空阶段会遇到"搬不走的块" ⇒ `ENOTSUP` ✓；扩容不受影响 ✓ |
| **`NLINK` / 链接块** | 不变 ✓：**同代**共享靠 `NLINK` ✓，**跨代**共享靠可达性 ✓ |

---

## 8. 不变量（新增，都可事后检查 ✓）

| # | 内容 |
|---|---|
| **I13** | 根表里每一项的 `gen` 都 **≤ anchor 的 `gen`** ✓，且**两两不同** ✓ |
| **I14** | 每个**保留世代**的根块必须存在 ✓，且在位图里置位 ✓ |
| **I15** | 凡被**任一保留世代**可达的块，位图里必须置位 ✓（否则 = 悬空引用 ✗）|
| **I16** | 待释放队列里的块，**不得**同时被任何保留世代可达 ✓（否则 = 提前释放 ✗）|

---

## 9. 失败模式

| 崩在 | 结果 |
|---|---|
| 根链接块写到一半 | A/B 双槽 ⇒ **旧槽**（还没有这个快照）或**新槽**（快照已记）✓，不会半个根表 ✓ |
| 提交后、清队列前 | 队列过期 ⇒ **少回收**几个块 ✓（重建时修正 ✓）|
| 重建位图时 | 位图还是旧的 ✓（dirty 标志要求重来 ✓）|

## 10. 待定项

1. **待释放队列放哪**：`stateflg` 扩展位 + 独立块，还是塞进根链接块的属性 ✓；
2. **根表上限**：链接块载荷 4032 B ⇒ 每项 ~16 B ⇒ 两百多个快照 ✓；超了怎么办（分片 / 树化 ✓）；
3. **删快照的时机**：只去表项 ✓，还是"去表项 + 立刻推进待释放" ✓；
4. **克隆**：复制根表 ✓，还是共享根表 + `NLINK` ✓；
5. **与 `--cow` 的关系**：快照是否隐含"必须按 COW 运行" ✓（倾向**是** ✓：没有 COW 就没有"不覆盖" ✓）。
6. **根表项指向的"根块"到底是什么**：是根链接块里那张**内容块表本身**（原地写），还是**单独的表块**
   （每代一份、可 COW）？若是后者，根链接块还要存"当前表块"的指针；这决定 §3 的提交点与根表项宽度。
