## 2. anchor 块（`block_type = 5`）

- head anchor 在 `start`，tail anchor 在 `start + region_len − 4096`。
- **`hdrbytes = 0x200`**：把全部 anchor 字段都纳入头部 CRC（`header_crc32` 覆盖 `[0, header_bytes)`）。
- **`payload_len = 0`**：anchor 没有"载荷"区，字段全在头部内。
- 通用块头的 `flags` 位图块语义在这里不用；anchor 自己的状态位在载荷字段 `flags`（偏移 128）。

### 2.1 块内布局：两大段（**卷头** + **pool 段**）

```
[0x000, 0x200) 【卷头】     必须有；hdrcrc 覆盖它
                  头基本信息 [0x000,0x040) + 几何/身份段 [0x040,0x100) + 状态段 [0x100,0x200)
[0x200, 0x3d0) 【pool 段】  可以有可以没有；自带 poolcrc
[0x3d0, 0x1000) 其余留空
```

> **概念名 vs tag 名**：文档正文里 `region_len` / `data_lo_logical` / `policy_state` 这类是**概念名**；
> anchor 块里真正写下的**字段名就是 tag**（`reglen` / `dlolog` / `polstate` …），一一对应。

**摆放原则（本次按它重排）**：

1. **同类的东西紧贴在一起** ✓ —— 成对 / 成组的字段连续摆放：谁的**类型**紧挨着它的**入口**，
   再跟着它的**尺寸**（"类型 → 入口 → 尺寸"✓）。于是有：`roottype` + `rootioff` ✓、
   `allotype` + `alloioff` + `allocnum` + `allosize` ✓、`policy` + `polstate` ✓。
2. **段的划分按"变不变"**：几何 / 身份段只在 mkfs、resize 时变 ✓；状态段每次提交都变 ✓。
   本次把 `policy` 从几何段**挪进状态段**（紧贴 `polstate` ✓）—— 代价是几何段不再包含"改策略"，
   好处是**分配策略这一族连在一起**，且几何段变成"**只随几何变化**"✓ 更纯 ✓。
3. **名字必须 ≤ 8 个 ASCII 字符** ✓（tag 是 8 字节定长 ✓）：`roottype` / `rootioff` 恰好 8 ✓；
   `alloctype` / `allocioff` 都是 **9 个字符，放不下** ✗ ⇒ 定名 **`allotype` / `alloioff`** ✓（对称 ✓）。

形式：**8 字节 ASCII 名（空格补齐）+ 它的值**，一个接一个；**每个字段恰好 16 字节**，
所以 `offs` 都是 16 的倍数；16 字节的值（uuid）是**裸值、不带 tag**。

#### 大段一：卷头 `[0x000, 0x200)`（`hdrbytes = 0x200`）

| offs | tag | value |
|---|---|---|
| `[0,f]` | `easypart` | **版本字符串**（如 `"0.0.0.0"`）—— 前 8 字节固定魔数 `easypart` |
| `[10,1f]` | `blktype ` | 块类型（u16，= 5） |
| `[20,2f]` | `hdrbytes` | **卷头**总长（u32，= `0x200`，段边界） |
| `[30,3f]` | `hdrcrc  ` | **卷头 CRC**（u32，覆盖 `[0, 0x200)`，本字段按 0 计） |
| `[40,4f]` | `reglen  ` | 区域总长（u64，含两个 anchor） |
| `[50,5f]` | `peer    ` | 互指另一份 anchor（i64 delta） |
| `[60,6f]` | `dlolog  ` | 数据区起点逻辑坐标 L（i64） |
| `[70,7f]` | `chunk   ` | chunk_shift（u8；12 ⇒ 4096） |
| `[80,8f]` | `geover  ` | 几何布局版本（u16） |
| `[90,9f]` | `geomflag` | 保留（u16，必须 0） |
| `[a0,af]` | （无 tag）| 卷 uuid（16 字节，**裸值**，放几何段末） |
| `[100,10f]` | `gen     ` | 单调 +1 的卷级提交计数（u64） |
| `[110,11f]` | `stateflg` | 位标志（u32；bit0 = clean） |
| `[120,12f]` | `roottype` | **根**：引用种类（u8；`0` 空卷、`1` **直接指**链式目录的第一个 dir 块、`2` 指向**链接块**（根目录的对象形态）；`3`–`255` 保留）|
| `[130,13f]` | `rootioff` | **根**：引用（i64 delta；含义由 `roottype` 决定 —— 都是**块地址**）|
| `[140,14f]` | `allotype` | **分配结构**：类型（u8；`1` = 扁平位图链、`2` = 分配器**对象**（结构放链接块里）`bitmap_OBJECT`） |
| `[150,15f]` | `alloioff` | **分配结构**：入口（i64 delta → 链头 / 链接块 / 树根，由 `allotype` 决定） |
| `[160,16f]` | `allocnum` | **分配结构**：块数（u32；链长 / 对象覆盖块数，交叉校验用） |
| `[170,17f]` | `allosize` | **分配结构**：块字节和（u32，交叉校验用） |
| `[180,18f]` | `policy  ` | **分配策略**：id（u8；从几何段挪进来，紧贴 `polstate`） |
| `[190,19f]` | `polstate` | **分配策略**：游标 / 随机种子（u64）：让策略跨挂载连续 |
**两种根引用怎么区分** ✓（`rootioff` 的含义完全由 `roottype` 决定 ✓）：

| `roottype` | `rootioff` 是什么 | 相当于条目上的 | 为什么需要它 |
|---|---|---|---|
| `1` 链式目录 | **块地址**：根目录 dir 链的**第一个 dir 块** ✓ | `DIR_PTR` ✓ | 单根、无共享 —— 最省一跳 ✓ |
| `2` 链接块 | **块地址**：一个**链接块** ✓（载荷 = 根目录的内容块表）| `DIR_OBJECT` ✓ | 根目录要用**目录级 COW**（换根 = 一次块写）✓ |

两种就是"**直接指**"与"**经一层间接（链接块）**" ✓。
若将来要做**快照**（同一卷同时留住多代根 ✓），不必新增第三种 `roottype` ✗ —— 把"**编号 → 各代根块**"做成**根目录的链接块载荷里的一条属性**即可 ✓（链接块载荷本来就是 TLV 属性流 ✓），anchor 与 `roottype` 都不用动 ✓。
> 段起点：头基本信息 `0x000`、几何/身份段 `0x040`、状态段 `0x100`（**段边界是钉住的**，
> 所以 `offs` 会从 `0xa0` 跳到 `0x100`、从 `0x1a0` 到段末 `0x200` —— 中间都是**段内保留**）。
> 实际用到 `0x1a0`；`hdrcrc` 覆盖到段边界 `0x200`，保留区也一起校验 ✓。

> 和卷头的 `hdrcrc` 同一个套路：**先验 CRC，再信后面的字段** ✓。

### 2.2 一致性要求（I9：head 与 tail 必须一致）

**每次提交 head 与 tail 都要写，两份必须满足**：

1. **非 delta 字段逐一相等**：`reglen` / `uuid` / `dlolog` / `chunk` / `geover` / `geomflag` /
   `gen` / `stateflg` / `roottype` / `allotype` / `allocnum` / `allosize` / `policy` / `polstate`；
2. **delta 字段解算成绝对地址后相等**：`rootioff` → 根块；`alloioff` → 分配结构的入口块
   （`peer` 例外：head 与 tail 本来就互为对方的地址）；
3. **tag 顺序必须一致**（顺序僵化是"自描述"的代价）；三段的 CRC 各自校验。

**任一不满足 ⇒ 报错（`ESTALE`），不许猜。** 两个 anchor 不一样只有两种可能：
① 一次提交 / resize 没做完（撕裂）；② 调用方给的 `[start, region_len_hint)` 不对，读到的是**上一代** anchor。
两种都不该由读取方替人决定谁对，所以直接拒绝，并**把两边的字段都打印出来**。
诊断工具 `probe` 在这种状态下**仍然照常打印**（它只读、不拒绝）。

> `gen` 是单调的**卷级提交计数**，但**不用于挑赢家** —— 两份不一致一律拒绝。
> 原子性分层：**对象级**由链接块自己的 A/B 双槽保证（[`cow.md`](cow.md)）；
> **卷级**靠"头尾必须一致"把关。
>
> **校验权威是 `hdrcrc`**（覆盖 `[0, hdrbytes)` = **卷头** `[0, 0x200)`，一票决定）；
> **pool 段不在它覆盖范围内** ✓ —— 非池卷可以完全不管那几个字节 ✓；
> 池成员由 **`poolcrc`** 自己覆盖 `[0x200, 0x3d0)` ✓（一段一个 CRC，各管各的）。

**I5 提醒**：任何块都**不允许**保存"指向 anchor"的指针 —— anchor 是靠"区域首尾"这个位置约定找到的，
不是被指到的。这是"向左/向右扩展只需搬一个 4 KiB"的前提。

### 2.3 pool 段的规则（字段表见 §2.1 大段二）

* **判据只有一个 tag**：`"easypool"` 在（版本串非零）⇒ **这块盘属于某个池**；
  **不在**（全零 / 对不上）⇒ **当作没有 RAID 的普通卷用** ✓（不需要额外 flag ✓）
* **可以完全没有**：非池成员该段全零，卷头 CRC 也不管它 ✓
* **安全规则**：`easypool` 有效且 `memcount > 1` 时**必须经 vdev 层挂载**；
  当普通卷直接挂载要返回 `ENOTSUP`（否则读到的是"看起来正常其实错位"的条带列）
* 字段细节与仲裁见 [`raid.md`](raid.md)。

## 3. 挂载 / 发现流程

```
1. 调用方给出 [start, region_len_hint) ← 调用方给出的两个几何
2. 读 head@start；校验 easypart tag、blktype=5、hdrcrc
3. head 合法 → 按 head.reglen 定位 tail@(start + head.reglen − 4096) tail 的位置**由卷自己说**，不由 hint 或设备大小推
   若 region_len_hint != head.reglen，额外读一眼 hint 位置：
   那是"容器已改、卷还没 adopt"的情形
4. tail 同上校验
5. 两个都不合法            → 拒绝挂载（EINVAL）
6. 只有一个合法            → 用它；另一个按 §2.1 重建（写回去）
7. 都合法但不满足 §2.2 的两条（非 delta 字段相等 + delta 解算后相等）→ **拒绝**（ESTALE），
   打印两边字段
8. dev.size < region_len   → **拒绝**（EINVAL："容器比卷小，是不是被截断了？"）
   dev.size > region_len   → 允许挂载，但打印提示"容器比卷大，需要 resize 采纳"。
                             （卷只在自己 region_len 内读写，不会越界，所以不必强制只读）
9. 加载位图链，**校验 I7′**（见 [`1-alloc.md`](1-alloc.md) 的混合粒度一节）：链按 `logical_start` 递增、同层区域首尾相接、
   子区域落在父区域的某个单位内、**叶区域**的并集 == `[data_lo, data_hi)`
   不成立 → **拒绝写入**（ESTALE：链和 region_len 对不上 = 上次 resize 没做完）
10. 看 `stateflg` 的 bit0：clean → 直接用；dirty → 先重建位图（1-alloc.md）再转 clean
11. 按 `roottype` 读根：`1` ⇒ `rootioff` 指向链式目录（校验 `block_type=2`）；
    `2` ⇒ 指向链接块（校验 `block_type=3`，载荷是目录内容块表）；`0` ⇒ 空卷（视为无根）
```

第 3 和第 9 步的共同点：**凡"卷自己记的"和"调用方说的"可能不一致，就以卷自己记的为准**。
`reglen` 是卷里的真相，调用方说的长度与设备大小只是外部说法；一旦不一致就说明
"容器改了、卷还没跟上"，这时**绝不能**拿设备大小去猜卷尾在哪 —— 那正是撕裂状态。

## 5. 伸缩

四个方向（右扩 / 左扩 / 右缩 / 左缩）的具体动作、写顺序、收缩前提，见
[`1-alloc.md`](1-alloc.md)。anchor 层面的规则只有两条：

1. **扩容**：先改 anchor（`reglen` 变大 + head/tail 搬家），后写位图；
2. **缩容**：先写位图（区域裁掉），后改 anchor（`reglen` 变小）。
3. 左扩/左缩时 `data_lo_logical` 必须与 `data_lo` 同步 ∓N（[`layout.md`](layout.md) 的表）。
