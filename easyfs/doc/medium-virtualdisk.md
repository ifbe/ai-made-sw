# 虚拟磁盘（载体 · virtualdisk）

> **载体层文档**：讲「**把一个盘装进一个文件**」这套载体怎么用 ✓ —— 和
> [`medium-parttable.md`](medium-parttable.md) 同属"卷之外"那一层（分区表决定卷放在哪 ✓，虚拟磁盘决定
> 那个"盘"本身是个文件 ✓）。**卷格式**见 [`detail-layout.md`](detail-layout.md) / [`detail-common.md`](detail-common.md) ✓。
>
> 相关：[`medium-parttable.md`](medium-parttable.md)（分区表与「卷放在哪」）、[`5-anchor.md`](5-anchor.md)（`reglen` 与几何）、
> [`1-alloc.md`](1-alloc.md)（伸缩与容器大小）。

---

## 1. 载体分两类

| 类 | 是什么 | 例子 |
|---|---|---|
| **真载体** | 块设备 / 内存 | `/dev/sda` ✓、`/dev/sda1` ✓、内存块 ✓ |
| **虚拟磁盘** | 把"一个盘"**存在一个普通文件里** ✓ | `.img` ✓、`.vhd` ✓、`.vmdk` ✓、`.dmg` ✓ |

虚拟磁盘的价值 ✓：**盘是可复制、可分发、可进版本库外挂盘** ✓ —— 测试、CI、导出演示都用它 ✓；
而卷格式对它的要求**和真盘一样** ✓：只要"按偏移读 / 写" ✓（卷内不含绝对地址 ✓）。

---

## 2. 支持哪些容器

| 后缀 | 是什么 | 关键特征 | 能当卷载体 |
|---|---|---|---|
| `.img` / `.raw` | **裸文件** | 文件就是一个盘 ✓，大小 = 盘容量 ✓ | ✓ |
| `.vhd` | VHD（Virtual PC / Hyper-V）| **页脚 `conectix` 在文件尾** ✓；动态（按需增长 ✓）/ 固定（`--fixed` ✓）| ✓ |
| `.vmdk` | VMware 单文件稀疏盘 | **魔数 `KDMV` 在文件头** ✓；容量信息在文件内的 GD / GT 里 ✓；空盘很小（64 MiB ≈ 5 KiB ✓）| ✓ |
| `.dmg` | Apple UDIF（**未压缩**）| 元数据在**文件尾**（`koly` ✓）；常带压缩 / 校验 ✓ | ✗ |

**为什么 `.dmg` 不当工作载体** ✗：UDIF 是**分发容器**（常压缩、带分层校验 ✓），
用它当"能读能写的盘"既要处理压缩又要处理外来工具的写一致性 ✗ ⇒ 它只用于**建 / 看详情** ✓
（导出、给 macOS 用户看 ✓）。

---

## 3. 盘上的分区与「卷放在哪」

* `.vhd` / `.vmdk` / `.img` **都可以带分区表** ✓（MBR ✓ / GPT ✓）—— 工具会**自动解析** ✓；
* 选分区的规则与 [`medium-parttable.md`](medium-parttable.md) 完全一致 ✓：
  * 只有 1 个分区 ⇒ 自动选它 ✓；
  * 多个分区 ⇒ **要求显式给分区号** ✓（不替你猜 ✓）；
  * 没有分区表 ⇒ 按整盘 ✓；
  * 要把**整盘**当卷 ⇒ 显式写"从 0 开始" ✓。
* **偏移是自动加的** ✓：选中分区后，工具在它外面包一层"区域设备" ✓
  ⇒ 之后所有偏移 / 块号 / 路径都是**卷内坐标** ✓，卷**不知道**自己在盘上哪一块 ✓。

## 4. 和卷格式的关系（别混淆 ✓）

| 谁管什么 | 卷 | 容器 |
|---|---|---|
| 我有多大 | `reglen`（卷自己记 ✓）| 文件大小 / 虚拟盘声明的容量 ✓ |
| 我放在哪 | **不知道** ✓（卷内无绝对地址 ✓）| 分区起点 + 区域偏移 ✓ |
| 谁保护我 | anchor 双份 + CRC ✓ | **没有** ✗（容器坏了卷就坏 ✓）|

* 容器**比卷小** ⇒ 挂载**拒绝** ✓（像是被截断了 ✓）；
* 容器**比卷大** ⇒ 允许挂载 ✓ + 提示"需要采纳" ✓（用伸缩把卷长大 ✓，见 [`1-alloc.md`](1-alloc.md)）；
* 容器层**不在卷格式的保护范围** ✓：虚拟磁盘的文件头 / 页脚 / 元数据坏了 ⇒ 工具可能都认不出它 ✓
  ⇒ 备份时要**整份拷走** ✓（不是只拷卷的那一段 ✓）。

## 5. 稀疏与尺寸

| 容器 | 空盘占多少 | 说明 |
|---|---|---|
| `.img` | 取决于文件系统（`truncate` 出来的基本不占 ✓）| 最省事 ✓ |
| `.vhd` 动态 | 只占已写部分 ✓（有上限 ✓）| 适合"会长大的盘" ✓ |
| `.vhd` 固定 | **满尺寸** ✓ | 适合"要真盘 IO 行为" ✓（预分配 ✓）|
| `.vmdk` 单文件稀疏 | 只占已写部分 ✓（64 MiB 空盘 ≈ 5 KiB ✓）| 跨平台交换方便 ✓ |
| `.dmg` | 视压缩而定 ✓ | 只导出 ✓ |

---

## 6. 什么时候用哪种

| 场景 | 建议 |
|---|---|
| 测试 / CI（要快、要小）| `.img` ✓（或 `.vhd` 动态 ✓）|
| 发给别人一个"盘"（VMware / VirtualBox）| `.vmdk` ✓（单文件 ✓）|
| 发给别人一个"盘"（Hyper-V）| `.vhd` ✓（固定更稳 ✓）|
| 装进笔记本给 macOS 看 | `.dmg` ✓（只读 ✓）|
| 模拟真实介质（写入行为、容量固定）| `.vhd` **固定** ✓ |
| 真盘 / U 盘 | 不用虚拟磁盘 ✓ —— 直接给设备节点 ✓（[`medium-parttable.md`](medium-parttable.md) 的"卷放在哪"）|

---

## 7. 不要依赖的语义

| 不要依赖 | 原因 |
|---|---|
| 在虚拟磁盘上"同时"被别的工具打开写 | 没有跨工具锁 ✗；两边的缓存会打架 ✓ |
| 容器的元数据也被卷格式校验 | 容器在卷格式之外 ✓（卷只认 `reglen` ✓）|
| 稀疏容器的"洞"语义 | 洞读出来是 0 ✓，但**不保证**空洞位置稳定 ✓ |
| 用 `.dmg` 当工作盘 | 见 §2 ✗ |
| 虚拟磁盘里的"绝对扇区号" | 卷内坐标是相对的 ✓（换盘不用改卷 ✓）|

---

## 8. 待定项

1. **`.vhdx` / `.qcow2`** 要不要支持 —— 它们带快照 / 压缩语义 ✓，超出"盘装进文件"的范围 ✓（倾向**不支持** ✗）；
2. `.dmg` 的**只读挂载**要不要做 ✓（现在只建 / 看 ✓）；
3. 虚拟磁盘要不要**内置分区表**的默认值 ✓（现在用分区表命令自己建 ✓）；
4. 大容量（≥ 2 TiB）容器的稀疏策略 ✓（BAT / GT 的条目数会涨 ✓）。
